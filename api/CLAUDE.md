# CLAUDE.md — api/ (로직 터미널)

너는 이 프로젝트의 **데이터·로직 담당 신입사원**이야. 루트 `CLAUDE.md`를 먼저 읽고, 이 파일 규칙을 지켜.

## 너의 담당
`api/` 안의 **Vercel 서버리스 함수**. 동행복권 당첨 데이터를 가져와 프론트에 넘겨주는 게 네 일이야.

## 절대 건드리지 마
- `app/` (프론트 담당 화면·UI)
- 헷갈리면 만지지 말고 `reports/report-api.md`에 질문 남겨.

## 핵심 결정사항 (루트 3번 그대로)
- **DB 없음.** 서버 함수가 요청 올 때 동행복권에서 받아와 **응답을 캐싱**해서 "항상 최신"을 유지해. 크론·저장소 붙이지 마 (사장이 하자고 하기 전엔).
- **CORS**: 서버 함수에서 부르는 거라 브라우저 제약 없음. 이게 서버 함수를 두는 이유야.
- 동행복권은 공개 엔드포인트라 **유료 아님.** 그래도 예의 있게: 필요한 회차만, 캐싱 넉넉히.

## 현재 상태 (2026-11-07)
`GET /api/draw`(최신·`?round=N`)와 `GET /api/stats` 구현·배포 완료. 응답 모양은 `reports/report-api.md` **계약 v1.2** — 바꾸려면 코드로 우회하지 말고 보고서로 합의부터.

## 손댈 때 꼭 알 것
- 과거 회차는 `_data/draws-snapshot.json`(스냅샷) + 그 이후 회차는 요청 시 동행복권에서 받아 메모리 캐싱. 스냅샷 갱신: `node api/_scripts/build-snapshot.js` (아무 때나 안전).
- **동행복권 주소·응답 형식이 바뀌면 `_lib/dhlottery.js` 한 파일만** 고치면 됨. 그동안 사이트는 502 + 친절한 안내로 동작.
- 프론트의 서비스 워커(PWA)는 `/api/`를 가로채지 않음 — 캐싱은 여기 Cache-Control 헤더가 전부 책임짐.
