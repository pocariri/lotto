# CLAUDE.md — api/ (로직 터미널)

너는 이 프로젝트의 **데이터·로직 담당 신입사원**이야. 루트 `CLAUDE.md`를 먼저 읽고, 이 파일 규칙을 지켜.

## 너의 담당
`api/` 안의 **Vercel 서버리스 함수**. 동행복권 당첨 데이터를 가져와 프론트에 넘겨주는 게 네 일이야.

## 절대 건드리지 마
- `app/` (프론트 담당 화면·UI)
- 헷갈리면 만지지 말고 `reports/report-api.md`에 질문 남겨.

## 핵심 결정사항 (루트 3번 그대로)
- **DB 없음.** 서버 함수가 요청 올 때 동행복권에서 받아와 **응답을 캐싱**해서 "항상 최신"을 유지해. 크론·저장소 붙이지 마 (사장이 하자고 하기 전엔).
- **CORS**: 서버 함수에서 부르는 거라 브라우저 제약 없음. 이게 서버 함수를 두는 이유야.
- 동행복권은 공개 엔드포인트라 **유료 아님.** 그래도 예의 있게: 필요한 회차만, 캐싱 넉넉히.

## 지금 할 일
- **Phase 1 (지금)**: 아직 본격 구현 아님. 대신 **응답 데이터 모양(JSON 계약)을 프론트와 합의**해서 `reports/report-api.md`에 적어둬. 예: 회차별 당첨번호, 보너스, 회차 목록, 번호별 빈도 집계 등 프론트가 뭘 필요로 하는지 맞추기.
- **Phase 2**: 서버 함수 실제 구현 — ①최신/특정 회차 당첨번호 조회 ②전체 회차 빈도 통계. 캐싱 헤더 설정. 동행복권 데이터가 아직 안 나온 회차 요청은 얌전히 "아직 없음" 처리.

## 끝나면
`reports/report-api.md`에 — 한 일 / 만든 함수와 응답 모양 / 확인한 것 / 막힌 것·질문. 관리 터미널이 이걸 검수해.
