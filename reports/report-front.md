# Phase 4 보고 — 추첨 모드 (2026-07-13)

사장 지시로 Phase 3(사진 인식)는 하지 않기로 확정, Phase 4(추첨 모드)를 진행. 계획을 먼저 보고하고 승인받은 뒤 구현함.

## 한 일

- **추첨 탭 picker에 "추첨 모드" 추가**: 완전 랜덤(기본) / 핫 / 콜드 칩 3개 + 강도 조절(약하게/세게 — 핫·콜드를 골랐을 때만 표시, 기본 약하게. 사장이 2단 버튼으로 결정).
- **방식은 "응모권"**: 모든 번호가 기본 응모권 1장 + 빈도 보너스(약하게 최대 +1장=2배 차이, 세게 최대 +4장=5배 차이). 기본 1장은 절대 안 사라지므로 어떤 강도에서도 모든 번호가 최소 확률을 유지 — 특정 번호 고착 불가. 빈도가 전부 같으면 완전 랜덤과 동일.
- **데이터는 통계 탭 것 재사용**: `GET /api/stats`의 `frequency` 그대로. **`api/` 폴더와 `js/api.js`는 무변경** (기존 캐시 그대로 활용). 핫/콜드를 고르는 순간 미리 받아둠.
- **실패 폴백**: 추첨 시점까지 통계를 못 받으면 완전 랜덤으로 뽑고, 결과 화면에 금색 안내 "통계를 불러오지 못해 이번엔 완전 랜덤으로 뽑았어요" 표시.
- **정직 원칙 (사장 지시)**: "유리한 번호/확률 높은 번호" 표현 일절 없음. 모드 설명은 추첨기 동작 그대로("많이/적게 나온 번호가 뽑힐 확률이 높아져요"), 그 아래 상시 안내: "과거 빈도는 다음 추첨에 영향을 주지 않습니다. 번호를 고르는 재미를 위한 기능이에요." 핫/콜드는 완전히 동등하게 배치.
- **고정/제외와 결합**: 고정 먼저 확정 → 제외는 응모함에서 제거 → 남은 자리만 가중 추첨. 기존 검증(후보 6개 미만 차단) 그대로.
