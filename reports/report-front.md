# Phase 2 전환 보고 (2026-07-07)

## 한 일 — mock → 실데이터(계약 v1.2) 전환 완료

- **`js/api.js`**: mock 삭제, 실 fetch로 전환. `{ok, data}` 겉봉투 해석, `ok:false`면 `error.message`를 그대로 사용자에게 표시, 성공 응답은 주소별 캐싱(지나간 회차는 안 바뀜), 실패는 캐싱 안 함(재시도 가능).
- **`js/check.js`**: `nums`→`numbers`. 회차 chip은 `GET /api/draw`의 최신 회차 번호에서 최근 5개(latest, latest-1, …) 생성 — 1회차 아래로는 안 만든다. chip 선택 시 `?round=N` 호출: 로딩 문구 표시, 기다리는 동안 다른 chip을 누르면 늦게 온 응답은 무시. 결과 카드에 **1등 당첨금 줄 추가**: "이 회차 1등: N명 · 1인당 X원"(콤마 표기), `winners`가 0이면 **"이 회차는 1등 당첨자 없음"**.
- **`js/stats.js`**: 자주/드문 번호·홀짝·기준 회차를 직접 계산하지 않고 서버 값(`mostFrequent`/`leastFrequent`/`oddEven`/`latestRound`)을 그대로 사용(동률 규칙이 서버에 있으므로). 홀짝만 개수→퍼센트 변환해서 막대를 그린다.
- **`js/main.js`**: 상단 "제 N회" 라벨을 실데이터로. 당첨확인 탭과 같은 캐시를 써서 중복 호출 없음.
- **`index.html` / CSS**: 당첨확인·통계 탭에 로딩/오류 문구 자리(`status-note`, 오류는 금색), 결과 카드에 1등 당첨금 줄(`prize-line`) 추가.
- **검증 도구를 `app/test/`에 정리** (사장 지시): `local-server.js`(app/ 정적 + api/ 함수를 Vercel처럼 한 포트에), `test-lottery.js`(순수 로직), `browser-test.js`(헤드리스 크롬 클릭 검증, 스크린샷은 `test/shots/`).
